# Αξιολόγηση (κεφάλαιο 5 της πτυχιακής)

Scripts και αποτελέσματα των μετρήσεων που απαντούν στα ερευνητικά ερωτήματα ΕΕ1–ΕΕ3 και στις μη λειτουργικές απαιτήσεις NFR-01, NFR-02, NFR-03 και NFR-09.

## Προαπαιτούμενα
- .NET SDK 10 και Docker Desktop σε λειτουργία (τα πειράματα σηκώνουν δική τους PostgreSQL 16 μέσω Testcontainers).
- Για το Lighthouse: Node.js 20 και το πλήρες stack (`docker compose -f docker-compose.full.yml up --build`).

## Εκτέλεση

```powershell
# ΕΕ1 (υπερκρατήσεις με/χωρίς κλείδωμα) + ΕΕ2 (χρόνοι απόκρισης)
./evaluation/run-evaluation.ps1

# Κανονικές δοκιμές (περιλαμβάνουν την απομόνωση tenant σε HTTP — ΕΕ3)
cd backend; dotnet test
```

Τα πειράματα βρίσκονται στο `backend/tests/GymBooking.Tests/Evaluation/` και τρέχουν **μόνο** με `RUN_EVALUATION=1`, ώστε το απλό `dotnet test` να μένει γρήγορο.

## Αρχεία αποτελεσμάτων (`evaluation/results/`)

| Αρχείο | Περιεχόμενο |
|---|---|
| `environment.txt` | Hardware, λειτουργικό, runtime και ρύθμιση της βάσης κατά τη μέτρηση |
| `ee1_concurrency.csv` | Μία γραμμή ανά επανάληψη: υλοποίηση (`locked` / `naive`), αιτήματα N, χωρητικότητα C, επιτυχίες, επιβεβαιωμένες κρατήσεις στη βάση, υπερκρατήσεις, διάρκεια |
| `ee2_latency_raw.csv` | Κάθε μεμονωμένο HTTP αίτημα: σενάριο, ταυτόχρονοι χρήστες, επανάληψη, χρόνος (ms) |
| `ee2_latency_summary.csv` | Μέσος όρος, p50, p95, τυπική απόκλιση του p95 ανάμεσα στις επαναλήψεις και μέγιστο, ανά σενάριο και επίπεδο ταυτοχρονισμού |
| `lighthouse/*.json` | Αναφορές Lighthouse (προσβασιμότητα) για τις κύριες οθόνες |

## Σημειώσεις μεθοδολογίας
- Η υλοποίηση `naive` (χωρίς κλείδωμα) υπάρχει **μόνο** στον κώδικα του πειράματος, ως baseline· δεν χρησιμοποιείται από την εφαρμογή.
- Όλα τα αιτήματα κάθε γύρου ξεκινούν ταυτόχρονα (κοινή «πύλη» εκκίνησης).
- Το API εκτελείται in-process (TestServer)· οι χρόνοι δεν περιλαμβάνουν καθυστέρηση δικτύου.
