Gym Booking — Implementation Plan

Multi-tenant SaaS για κρατήσεις & προγράμματα γυμναστηρίου (πτυχιακή + βάση προϊόντος).

Goal: Multi-tenant web app· Angular Nx monorepo ↔ .NET Web API ↔ PostgreSQL.

Architecture: Nx monorepo (customer mobile-first + staff desktop-first + shared libs) · layered .NET (EF Core, Identity+JWT) · shared-DB multi-tenancy με TenantId + EF global query filters.

Tech: Angular (Nx, Material, Tailwind, Signals) · .NET 8 · EF Core · PostgreSQL · Identity+JWT · Serilog · xUnit + Testcontainers · Docker · GitHub Actions.

Docs: spec · plan (md) · git note

Δομή του plan: Setup + Φάση 1 = πλήρως αναλυτικά (ξεκίνα από εδώ). Φάσεις 2–8 = outline· κάθε μία επεκτείνεται σε αναλυτικά bite-sized tasks όταν φτάνουμε εκεί (τότε τα paths/APIs θα είναι γνωστά).

SETUPSetup ~14h

Task 1 · Nx workspace + 2 apps

Create: gym-booking/ (Nx workspace)
☐ 1. Nx workspace (apps preset): 
npx create-nx-workspace@latest gym-booking --preset=apps --packageManager=npm --nxCloud=skip
cd gym-booking
npm i -D @nx/angular
☐ 2. Τα δύο apps: 
npx nx g @nx/angular:application customer --style=scss --routing=true --standalone=true

OUTLINEΦάσεις 2–8

Κάθε φάση = δικό της σετ bite-sized TDD tasks, που γράφονται όταν ξεκινά (τότε paths/DTOs υπάρχουν). Εδώ μόνο το περίγραμμα + τα tricky σημεία.

Φ2 · ClassType/ClassSession CRUD + instructor ~12h

  • Entities ClassType, ClassSession (+ migrations, soft-delete flags, UTC dates).
  • Core services + Instructor endpoints (CRUD, one-off sessions, capacity).
  • staff app: instructor σελίδες (λίστα/δημιουργία sessions, συμμετέχοντες).
  • Tests: authorization (instructor/admin), tenant isolation νέων entities.

Φ3 · 🔥 Booking core (atomic) + tests ~14h

Το «καρδιά» της εφαρμογής — no overbooking σε ταυτόχρονες κρατήσεις.
  • Booking, WaitlistEntry entities + migrations.
  • Atomic booking (TDD): transaction + SELECT … FOR UPDATE (raw SQL με parameters) → check bookedCount < capacity → create → increment. Concurrency test.
  • Anti-double-booking (ίδιο/overlapping session).
  • Cancel + επιστροφή θέσης. customer app: book/cancel UI.

Φ4 · Weekly schedule + φίλτρα + customer dashboard ~12h

  • GET /sessions?week=&filters (τύπος/instructor/μέρα).
  • customer: εβδομαδιαίο πρόγραμμα (mobile-first), διαθεσιμότητα, φίλτρα.
  • Dashboard: επερχόμενες + ιστορικό.

Φ5 · Subscriptions/plans + consumption ~12h

  • MembershipPlan (SessionPack|Unlimited), Subscription (+ migrations).
  • Consumption: SessionPack → decrement remaining (μέσα στο atomic transaction)· Unlimited → validFrom/validTo. Cancel → refund αν εντός policy.
  • staff (admin): plans + χειροκίνητη ανάθεση συνδρομής. customer: υπόλοιπο/ισχύς.

Φ6 · Waitlist + cancellation policy ~10h

  • Join waitlist όταν γεμάτο· auto-promote #1 σε cancel (transaction).
  • Policy: block ακύρωσης < Tenant.CancellationHours.
  • (SHOULD: recurring template generation· background job Hangfire/Quartz.)

Φ7 · Admin/staff dashboard + responsive QA ~12h

  • staff admin: χρήστες/ρόλοι, εποπτεία κρατήσεων, tenant settings.
  • Responsive QA customer (mobile) + staff (desktop).
  • (SHOULD: SignalR live availability — hub SpotsUpdated + Signals· emit από single point του booking service.)

Φ8 · Hardening + security + deployment ~12h

  • Security pass: OWASP checklist, resource-ownership παντού, analyzers· (SHOULD: rate limiting/lockout, refresh rotation, httpOnly cookie).
  • Seed/demo data (2 tenants → δείξε isolation).
  • Dockerize: Dockerfile Api + Dockerfile (nginx) Angular + compose· CD job (build→ghcr.io→SSH deploy, manual approval).
  • (SHOULD: PWA — πρώτο που κόβεται.) ER diagram + nx graph για την πτυχιακή.
